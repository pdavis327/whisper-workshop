What this briefing is for

Two things the room should be able to say

  • How to find audio models in the OpenShift AI catalog, and why turbo is the wrong catalog pick when you need native translation.

The workload

Voice is not another chatbot

What they already know

Granite on KServe: one InferenceService, one GPU, token-authenticated route, OpenAI client.

What is different

The payload is multipart audio, not JSON chat. Pointing a playground at Whisper fails.

Same serving platform. Different HTTP API. That is the whole technical story.

Why on-prem ASR

Start where the calls already are

ASR (automatic speech recognition) turns speech into text. Cloud ASR sends that voice off-site.

Contact centers

Every call is customer PII. Recordings already sit on the operator network.

Dispatch / public safety

Radio and incident audio is regulated and time-critical. It cannot traverse a public API.

Telecom

Voice traffic and call recordings stay on the carrier network — by architecture, not by preference.

Latency

On-cluster also means fewer milliseconds

  • You skip the WAN upload of bulky audio to a public-cloud ASR.
  • You skip the SaaS queue on the other side of that hop.
  • Transcription and speech-to-English run on the GPU beside the recordings.

Privacy and speed are the same architecture: the audio never leaves the building.

Say this out loud

What “faster” does and does not mean

True

End-to-end path

No internet round-trip, no audio leaving the datacenter. For contact-center and dispatch traffic that already lives on-prem, that hop dominates.

Not the claim

Raw decode vs a hyperscaler

We are not saying large-v3 beats a cloud Whisper API on GPU speed. Turbo is the latency SKU. Large-v3 is the SKU that still translates.

How vLLM exposes Whisper

OpenAI-compatible — audio, not chat

POST /v1/audio/transcriptions  →  speech to text (source language)
POST /v1/audio/translations  →  speech to English text
GET  /v1/models               →  served-model-name

HTTPS + Bearer token on an OpenShift Route. Same client libraries you already use for chat — different paths.

Translation is a product word

Whisper translates into English. Full stop.

  • Transcription keeps the source language.
  • Translation is speech → English only, and only on a non-turbo checkpoint.
  • Spanish ↔ German (or any arbitrary pair) is a second model, not this API.

Catalog in 3.5

Audio models are on the shelf now

AI hub → Models → Catalog. Search audio, speech, whisper, or voxtral.

Whisper large

Non-turbo checkpoint. Native /v1/audio/translations. Valid catalog path when translation matters.

Whisper turbo

Fast private STT (speech-to-text). vLLM: turbo does not support translating.

Voxtral

Mistral speech model. Voice-agent / understanding story — not a Whisper drop-in.

Do not confuse the shelf

Voxtral is a different product

  • It is a speech model on the same platform — good.
  • It is not Whisper’s OpenAI audio API (/v1/audio/transcriptions + /v1/audio/translations).
  • Save it for a voice-agent conversation. This workshop proves Whisper.

What we will actually serve

This lab: openai/whisper-large-v3 as a modelcar

  • Catalog is how a data scientist finds a supported ASR model.
  • A modelcar is how you own the weights — versioned OCI, pull at serve time.
  • Same vLLM NVIDIA GPU runtime as Granite. Different storageUri and Whisper args.

We are not fighting the catalog. We are matching weights to the customer outcome.

Leave-behind

Platform story in one breath

  • Stay on-cluster because the audio is PII — and because you skip the cloud hop.
  • Call it like OpenAI — /v1/audio/transcriptions and /v1/audio/translations.
  • Read the catalog card — turbo does not translate; Voxtral is not Whisper; large-v3 does.
